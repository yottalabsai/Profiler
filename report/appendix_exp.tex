\subsection{Prototype Automation via Claude Code Plugin}
\label{sec:appendix:plugin}

As a prototype implementation, \sys includes a Claude Code plugin that automates the
closed-loop protocol via a single \texttt{/optimize workload.py} command.  The plugin orchestrates five
specialized LLM agents---\textbf{capture-agent}, \textbf{optimization-strategist},
\textbf{backend-engineer}, \textbf{validation-agent}, and \textbf{/report}---covering all
pipeline stages from baseline capture through cross-profile comparison.  Evaluating whether
agent-generated optimization backends reproduce the manually-derived speedups reported in
\secref{sec:experiments} is left for future work.


\subsection{Additional Limitations}
\label{sec:appendix:limitations}

\textbf{\ncu replay timing inflation.}
All \texttt{duration\_ns} values in \texttt{profile.json} reflect \ncu's serialized
replay execution, which runs 2--5$\times$ slower than real wall-clock execution.
Values should be used for relative comparison only; \texttt{torch.cuda.Event} timing
is authoritative for absolute latency.

\subsection{FX Graph Pass Pseudocode}
\label{sec:appendix:passes}

The optimization framework applies FX graph transformations across three IR levels
(\secref{sec:threelevel}); a single backend combines passes from all three.
Algorithms~\ref{alg:gpt2_backend} and~\ref{alg:sdpa_backend} show the complete backends
for the two compiled case studies: counter-driven diagnosis selects passes, which are
composed into a single \texttt{torch.compile} call across all three levels.  All passes
are defensive---if the target pattern is absent the pass logs a warning and returns the
graph unmodified.

\begin{algorithm}[H]
\caption{GPT-2 Profile-Guided Backend (all three IR levels)}
\label{alg:gpt2_backend}
\begin{algorithmic}[1]
\Require Attributed profile $P$ from \sys; model $M$
\Ensure Optimized compiled model

\State \textit{// Counter-driven diagnosis}
\State $\textit{tc} \gets P[\{\texttt{aten::mm},\texttt{aten::addmm}\}].\texttt{tensor\_core\_active\_pct}$
  \Comment{0\% in baseline; GEMM family is 87.5\% of attributed runtime}
\State $\textit{sdpa\_masked} \gets \exists\,n \in P : n.\textit{name} = \texttt{aten::sdpa} \wedge n.\textit{attn\_mask} \neq \texttt{None}$

\State
\State \textit{// Level 1 --- Functional IR (pre-AOTAutograd decomposition)}
\State \textit{// Causal-mask subgraph only detectable before AOTAutograd lowers shared nodes}
\If{$\textit{sdpa\_masked}$}
  \For{each SDPA node $n$ with explicit \textit{attn\_mask} or $\textit{is\_causal} = \texttt{False}$}
    \State replace $n$ with \texttt{F.sdpa}$(q,k,v,$ \texttt{attn\_mask=None, is\_causal=True}$)$
  \EndFor
  \State \texttt{graph.eliminate\_dead\_code()}
    \Comment{removes \texttt{constant\_pad\_nd} / \texttt{scalar\_tensor} / \texttt{where} mask chain (48 nodes)}
\EndIf

\State
\State \textit{// Level 2 --- Aten IR (post-AOTAutograd)}
\If{$\textit{tc} = 0$}
  \For{each node $n$ with target $\in \{\texttt{aten.mm},\texttt{aten.addmm}\}$ and dtype $= \text{fp32}$}
    \State cast operands to bf16 via \texttt{prims.convert\_element\_type}
      \Comment{fp32 SIMT $\to$ bf16 Tensor Core; 210 $\to$ 96 registers/thread}
    \State insert fp32 cast-back after $n$; rewire users
  \EndFor
  \State fold adjacent \texttt{convert\_element\_type} pairs
    \Comment{cast-cancellation: eliminates redundant fp32$\leftrightarrow$bf16 round-trips}
\EndIf

\State
\State \textit{// Level 3 --- Inductor configuration}
\State $\texttt{inductor\_config.freezing} \gets \texttt{True}$
  \Comment{weight pre-packing for bf16 GEMM autotuning}
\State $\texttt{inductor\_config.max\_autotune} \gets \texttt{True}$

\State \Return \texttt{torch.compile}$(M,\ \texttt{backend=custom\_backend})$
\end{algorithmic}
\end{algorithm}

\noindent\textit{Implementation note:} \texttt{prims.convert\_element\_type} is used in
place of \texttt{aten.\_to\_copy} because on torch~2.11 the latter is registered as both
a fallback and a decomposition; inserting it into an already-decomposed Aten graph raises
an assertion inside \texttt{compile\_fx}.

\begin{algorithm}[H]
\caption{SDPA Attention Profile-Guided Backend (all three IR levels)}
\label{alg:sdpa_backend}
\begin{algorithmic}[1]
\Require Attributed profile $P$ from \sys; model $M$
\Ensure Optimized compiled model

\State \textit{// Counter-driven diagnosis}
\State $\textit{tc} \gets P[\{\texttt{aten::mm}\}].\texttt{tensor\_core\_active\_pct}$
  \Comment{0\% in baseline over QKV projection GEMMs}
\State $\textit{occ} \gets P[\{\texttt{aten::mm}\}].\texttt{achieved\_occupancy}$
  \Comment{16.6\% in baseline}

\State
\State \textit{// Level 1 --- Functional IR (pre-AOTAutograd decomposition)}
\State \textit{// Shared LayerNorm activation only visible before AOTAutograd copies it per consumer}
\If{$\textit{occ} < 20\%$}
  \For{each activation $x$ with $\ge 3$ bias-free \texttt{F.linear} consumers}
    \State $W_\text{fused} \gets \texttt{aten.cat}([W_q,W_k,W_v],\ \texttt{dim=0})$
      \Comment{shape $[3D,D]$}
    \State replace three $[B,T,D]$ \texttt{F.linear} calls with one $[B,T,3D]$ call
      \Comment{3 serial 128-block launches $\to$ 1 384-block launch}
    \State slice output to $q_\text{out},k_\text{out},v_\text{out}$ and rewire users
  \EndFor
\EndIf

\State
\State \textit{// Level 2 --- Aten IR (post-AOTAutograd)}
\If{$\textit{tc} = 0$}
  \For{each node $n$ with target $\in \{\texttt{aten.mm},\texttt{aten.addmm}\}$ and dtype $= \text{fp32}$}
    \State cast operands to bf16 via \texttt{prims.convert\_element\_type}
      \Comment{switches SDPA dispatch: \texttt{fmha\_cutlassF\_f32} $\to$ \texttt{fmha\_cutlassF\_bf16}}
    \State insert fp32 cast-back after $n$; rewire users
  \EndFor
\EndIf

\State
\State \textit{// Level 3 --- Inductor configuration}
\State $\texttt{inductor\_config.freezing} \gets \texttt{True}$
  \Comment{aligned weight layout for bf16 GEMM autotuning}
\State $\texttt{inductor\_config.max\_autotune} \gets \texttt{True}$

\State \Return \texttt{torch.compile}$(M,\ \texttt{backend=custom\_backend})$
\end{algorithmic}
\end{algorithm}

The LSTM case study (\secref{sec:cs:lstm}) requires no FX pass: \texttt{nn.LSTM}
triggers a hard Dynamo graph break, so no recurrent nodes appear in the compiled graph.
The corrective fix (routing to cuDNN's fused Tensor-Core RNN) takes effect purely by
allowing eager execution to proceed through \texttt{torch.\_VF.lstm} without forcing
the recurrent region into a compiled subgraph.  This is why all registered FX passes for
the LSTM backend report \texttt{NOT\_APPLIED} in validation logs while the workload
still achieves the largest speedup in the suite (3.63$\times$).
